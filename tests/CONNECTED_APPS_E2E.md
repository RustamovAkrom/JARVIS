# Connected Apps E2E verification

This pack separates deterministic regression tests from tests that contact real accounts and MCP servers. The live tests are opt-in; they skip when the corresponding environment variables are absent. No OAuth tokens, Telegram sessions, MCP headers or message content are printed by the tests.

## 1. Install the optional runtimes

From the repository root on Windows:

```powershell
uv sync --extra connected-apps --extra telegram-personal
```

The Connected Apps core remains usable without Telethon. Install the Telegram extra only when testing Telegram Personal.

## 2. Run deterministic end-to-end and UI runtime tests

```powershell
uv run pytest -q tests/test_connected_apps_extended_e2e.py tests/test_connected_apps_ui_runtime.py
```

These tests cover:
- Telegram verification-code login, 2FA challenge, session persistence/restoration, login cancellation, stable Telethon event-loop use, chat allowlist, read permissions, hard-disabled AI access and confirmation requirements for write/destructive tools.
- A real local MCP STDIO subprocess: initialization, tool discovery, tool call, health check, disconnect and reconnect.
- Serialized concurrent health checks.
- Connected Apps restart recovery using persisted protected credentials.
- Fail-closed handling of an unreadable protected credential.
- Qt panel startup, GitHub Reconnect/Disconnect button clicks, Telegram permissions dialog save, Telegram disconnect and Apps/MCP tab navigation.

## 3. Run real account and remote MCP API checks

Set only the environment variables for accounts/endpoints you are ready to test. Keep tokens out of source files, screenshots, issue reports and shell history. These variables are process-local and can be cleared with `Remove-Item Env:JARVIS_E2E_*`.

GitHub requires a token that can read the authenticated user's profile and repositories:

```powershell
$env:JARVIS_E2E_GITHUB_TOKEN = "<GitHub token with profile and repository read access>"
```

Google Calendar requires an access token with the `https://www.googleapis.com/auth/calendar.events` scope:

```powershell
$env:JARVIS_E2E_GOOGLE_ACCESS_TOKEN = "<Google Calendar access token>"
```

Telegram requires the optional Telethon package, API credentials from Telegram's developer portal, and a StringSession generated by logging into the intended test account:

```powershell
$env:JARVIS_E2E_TELEGRAM_API_ID = "<Telegram API ID>"
$env:JARVIS_E2E_TELEGRAM_API_HASH = "<Telegram API hash>"
$env:JARVIS_E2E_TELEGRAM_SESSION = "<Telegram StringSession>"
```

The Telegram live test checks session validity and lists chat metadata only. It deliberately does not read message contents or send, edit, forward or delete messages.

For an existing remote streamable-HTTP MCP server:

```powershell
$env:JARVIS_E2E_MCP_HTTP_URL = "https://your-test-server.example/mcp"
$env:JARVIS_E2E_MCP_HEADERS_JSON = '{"Authorization":"Bearer <test-token>"}'
```

For an existing remote SSE MCP server:

```powershell
$env:JARVIS_E2E_MCP_SSE_URL = "https://your-test-server.example/sse"
```

Run the live tests:

```powershell
uv run pytest -q tests/test_connected_apps_live_e2e.py -rs
```

Each configured live test performs a read-only request, verifies a successful MCP session, then disconnects the test client. Tests without configuration are reported as skipped.

## 4. Real OAuth browser flow — manual verification

The live token tests above verify provider APIs, but cannot replace a real interactive OAuth consent and loopback callback. Verify the browser flow in the JARVIS UI:

### GitHub
1. Open Settings → Connected Apps → GitHub → Connect.
2. Complete GitHub consent in the browser and return to JARVIS.
3. Confirm the card and native-app list show Connected.
4. Call the profile and repository read tools.
5. Restart JARVIS and confirm the persisted connection is restored.
6. Click Disconnect. Confirm the card changes to Not connected and the access token is no longer retained.
7. Click Connect again and complete consent. Confirm a new token works.

### Google Calendar
1. Open Settings → Connected Apps → Google Calendar → Connect.
2. Complete Google consent and verify the card reports Connected.
3. Read primary-calendar events.
4. In a dedicated test calendar, create a clearly named test event and approve the confirmation prompt. Verify the event appears, then remove the test event manually.
5. Restart JARVIS and verify the connection.
6. Disconnect using the selected-connection management controls, then connect again and verify a new access token works.

Do not use production calendars for write tests.

## 5. Telegram Personal — manual verification

1. Connect with the phone number, API ID and API hash for the test account.
2. Complete the Telegram verification code flow.
3. For an account with two-step verification enabled, confirm the password prompt appears and the login completes only after the correct password.
4. Restart JARVIS and verify the persisted MTProto session reconnects without requesting another code.
5. Open Permissions / chats. Select one non-sensitive test chat and save it to the allowlist.
6. Enable recent-message read permission and verify reading is limited to the selected chat.
7. Attempt the same read against a chat not in the allowlist; it must be denied.
8. Verify write actions request confirmation. Use only a private test chat if you manually test sending.
9. Disconnect and confirm the Telegram connection record and stored MTProto credentials are removed.

AI access to Telegram content must remain disabled.

## 6. MCP remote lifecycle — manual verification

Use dedicated test endpoints for both streamable HTTP and SSE:
1. Connect through the matching UI transport.
2. Verify initialization and tool discovery.
3. Run a harmless read-only tool.
4. Run a health check.
5. Simulate a temporary network outage and verify an actionable error is shown.
6. Restore the endpoint and use Reconnect.
7. Disconnect and verify the session is closed and no stale tools remain.

## 7. Windows UI regression checklist

The Qt tests exercise core high-risk dialogs and button paths offscreen. Before considering the feature fully verified, also run the visible UI in Windows:
- GitHub Connect, Reconnect, Disconnect and the selected-connection details.
- Google Calendar Connect, selected-connection Disconnect, health status and confirmation for event creation.
- Telegram Connect, verification code, 2FA, Permissions / chats, Cancel and Disconnect.
- MCP add STDIO / HTTP / SSE, Connect, Reconnect all, Check health, Block / Allow tool, Rename, Disconnect, Remove and diagnostics.
- Confirm busy states disable conflicting controls and every operation restores the controls after success and failure.

## 8. Full suite and CI

```powershell
uv run pytest -q
```

The GitHub Actions matrix also runs the full suite on Windows, Ubuntu and macOS, plus the PySide6 compatibility job. A green unit-test matrix is necessary but does not substitute for the real account checks and visible Windows UI checks above.

## Safety boundaries

The automated suite intentionally does not create Google Calendar events or send/edit/forward/delete Telegram messages. Those operations have external side effects and must remain confirmation-gated. The manual checklist uses test resources and explicit user approval for those steps.
