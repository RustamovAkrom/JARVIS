# Gemini в JARVIS: настройка, модели и эксплуатация

> Актуально на 9 октября 2026 г. Каталог Gemini меняется; перед заменой модели
> сверяйте идентификатор, доступность в регионе и квоты в [официальном каталоге](https://ai.google.dev/gemini-api/docs/models).

JARVIS использует Gemini как облачный интеллект для живого голосового диалога,
анализа текста и изображений, вызова инструментов и части фоновых задач. Это не
локальная LLM: для Gemini-функций нужен интернет и действующий ключ API.

## Быстрая настройка

1. Клонируйте репозиторий, создайте и активируйте виртуальное окружение, затем
   установите зависимости:

   ```powershell
   git clone https://github.com/RustamovAkrom/JARVIS.git
   cd JARVIS
   python -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```

   Для macOS/Linux активируйте окружение командой `source .venv/bin/activate`.
2. Откройте [Google AI Studio](https://aistudio.google.com/apikey), войдите в
   Google-аккаунт и примите условия сервиса.
3. Создайте или выберите проект, затем нажмите **Create API key**. Если рабочий
   проект не виден, импортируйте его в **Dashboard → Projects**.
4. Скопируйте ключ только в надёжное место. Его нельзя безопасно восстановить из
   репозитория или истории чата.
5. Запустите `python main.py`. При первом запуске JARVIS покажет окно
   **INITIALISATION REQUIRED**: вставьте ключ в **GEMINI API KEY**, проверьте
   автоматически выбранную ОС или выберите **Windows**, **macOS** либо **Linux**,
   затем нажмите **INITIALISE SYSTEMS**.
6. Проверьте микрофон и динамики в настройках приложения, затем начните голосовой
   или текстовый диалог.

JARVIS сохраняет ключ и выбранную ОС локально в `config/api_keys.json`. Этот файл
исключён из Git. Не создавайте и не коммитьте шаблон с настоящим ключом.

### Вариант для разработчиков: переменная окружения

Официальный SDK Gemini распознаёт `GEMINI_API_KEY` и `GOOGLE_API_KEY`. Текущий
рантайм JARVIS читает ключ из `config/api_keys.json`, поэтому переменная окружения
удобна для собственных скриптов и будущих доработок, но **сама по себе не заменяет
настройку JARVIS**.

PowerShell (только для текущего окна):

```powershell
$env:GEMINI_API_KEY = "ваш_ключ"
```

Постоянно для текущего пользователя Windows:

```powershell
[Environment]::SetEnvironmentVariable("GEMINI_API_KEY", "ваш_ключ", "User")
```

После постоянной настройки откройте новое окно терминала. Не вставляйте ключ в
`main.py`, `ui.py`, плагин, README, issue или скриншот.

## Как JARVIS использует AI

| Сценарий | Путь в проекте | Что происходит |
| --- | --- | --- |
| Голосовой разговор | `main.py` | Долгая двусторонняя сессия Gemini Live: аудио с микрофона, ответы голосом, текстовые транскрипции и вызовы инструментов. |
| Короткие и фоновые запросы | `core/gemini.py` | Централизованные одноразовые запросы для классификации, извлечения данных, анализа изображений и генерации. |
| Действия на компьютере | `actions/`, `plugins/` | Модель выбирает объявленный инструмент; код инструмента выполняет работу локально. Необратимые операции дополнительно требуют подтверждения UI. |
| Память | `memory/` | Сохраняется локально; JARVIS может извлекать релевантный контекст для диалога. |

Модель не получает «безграничный» доступ к ПК автоматически. Доступ определяется
загруженными actions/plugins, настройками ОС и подтверждениями пользователя.

## Модели, заданные в этой версии проекта

Идентификаторы ниже взяты из `core/gemini.py`; порядок — это поведение проекта,
а не универсальная рекомендация Google.

| Назначение | Основная модель | Резерв / детали |
| --- | --- | --- |
| Живой голосовой диалог | `models/gemini-3.1-flash-live-preview` | При ошибке доступности используется `models/gemini-2.5-flash-native-audio-preview-12-2025`. |
| Быстрые одноразовые задачи | Сперва текущая Live-модель | Далее лестница `gemini-2.5-flash-lite`, `gemini-3.5-flash-lite`, `gemini-3.1-flash-lite`, `gemini-flash-lite-latest`, `gemini-2.5-flash` и другие. |
| Сложные одноразовые задачи | Сперва текущая Live-модель | Далее приоритет у `gemini-2.5-flash`, затем Flash/Lite-модели. |
| Поиск с источниками | REST-модели | Live не используется: приложению нужны метаданные grounding в REST-ответе. |

### Важные примечания о версиях

- Основная Live-модель в текущем коде — preview-модель. Preview-идентификаторы
  могут иметь ограничения, меняться или исчезать; не обещайте их доступность
  всем ключам и регионам.
- Официальный каталог сейчас помечает `gemini-3.1-flash-live-preview` как legacy
  preview и рекомендует для новых Live-интеграций `gemini-3.8-live`. Это **не
  означает**, что имя можно без проверки заменить в конфиге: Live-модели
  отличаются допустимыми полями, голосами и возможностями. Сначала проверьте
  совместимость с используемой версией `google-genai`, конфигурацией в `main.py`
  и реальной учётной записью.
- Google ограничивает доступ новых проектов к некоторым моделям 2.5; поэтому
  резервная лестница может пропустить недоступную модель. Код JARVIS обрабатывает
  недоступность, квоты и временные сбои через cooldown/fallback.
- Не выбирайте модели только по названию. Для голоса нужен Live-совместимый
  endpoint, для поиска с источниками — REST-ответ с grounding metadata, для
  коротких фоновых задач обычно важнее скорость и стоимость.

## Замена модели: безопасный порядок

1. Посмотрите доступные модели для своего ключа в AI Studio и их официальные
   возможности/лимиты.
2. Найдите модель в `core/gemini.py`: `LIVE_MODELS` — голосовая сессия,
   `_LADDERS` — одноразовые вызовы.
3. Изменяйте одну группу за раз. Для Live сохраняйте префикс `models/`, если он
   нужен API-методу; для REST используйте идентификатор в формате, ожидаемом
   `client.models.generate_content`.
4. Проверьте запуск, голосовой диалог, вызов действия и временную недоступность.
   Не удаляйте рабочий fallback до успешной проверки.
5. Зафиксируйте в changelog дату, точный ID модели и причину изменения.

Не подменяйте Live-модель обычной текстовой моделью: это другой протокол и набор
входов/выходов. Не используйте модель перевода, transcribe или robotics как
универсальную замену голосового ассистента.

## Квоты, стоимость и диагностика

Квоты и цены зависят от модели, региона, тарифа и со временем меняются. Перед
активным использованием откройте [страницу тарифов Gemini](https://ai.google.dev/gemini-api/docs/pricing)
и Usage в AI Studio. Для платного проекта настройте бюджетные оповещения в Google
Cloud.

| Симптом | Что проверить |
| --- | --- |
| `API key not valid` | Ключ скопирован полностью, принадлежит нужному проекту и не был отозван. Введите новый ключ через UI. |
| `429` / quota | Лимиты и Usage; дождитесь сброса или используйте разрешённую резервную модель. Не запускайте бесконечные повторы. |
| `403` / модель недоступна | Регион, тариф, права проекта и поддержку модели для ключа. |
| `503`, `504`, таймаут | Статус сервиса, сеть и повтор позже; JARVIS временно исключает проблемные модели из попыток. |
| Нет голоса или микрофона | Разрешения ОС, выбранные устройства и сеть; Live требует непрерывного WebSocket-соединения. |

## Безопасность и приватность

- Относитесь к API-ключу как к паролю. При утечке сразу создайте новый ключ,
  обновите JARVIS, отключите старый и проверьте Usage/биллинг.
- В AI Studio ограничьте стандартный ключ только Gemini API; новые ключи могут
  быть authorization keys, привязанными к сервисному аккаунту.
- Для публичного веб- или мобильного продукта не встраивайте ключ в клиент:
  используйте серверный посредник или короткоживущие токены.
- До отправки экранов, файлов или камеры учитывайте, что эти данные могут быть
  переданы в Gemini для анализа. Не включайте такие функции при работе с
  конфиденциальными данными без оценки политики организации.
- Отключайте ненужные плагины и проверяйте действия, которые могут отправлять
  сообщения, изменять файлы или управлять системой.
