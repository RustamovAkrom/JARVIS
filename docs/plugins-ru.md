# Плагины JARVIS: каталог и разработка

[English](plugins.md) · [Главная документация](../README_ru.md)

Плагин — дополнительный инструмент или панель, загружаемая из `plugins/`. Менеджер находится в **SETUP → PLUGINS**.

## Включение, отключение и удаление

- Переключатель **ON/OFF** сохраняется в `config/api_keys.json` в объекте `plugins_enabled`.
- Плагины обнаруживаются при запуске. Переключение уже загруженного модуля применяется без перезапуска; отключённый плагин больше не предлагается модели.
- Чтобы удалить функцию, удалите её `.py`-файл из `plugins/`. Сначала проверьте импорты: файлы `plugins/_*.py` — общие helpers, от которых могут зависеть несколько плагинов.
- Сохранённая конфигурация плагина может остаться в JSON после удаления кода. Удаляйте её отдельно только после резервного копирования и проверки namespace.
- **PLUGIN SETTINGS** показывает поля, объявленные через `PLUGIN_SETTINGS`; кнопка TEST доступна только при наличии тестового действия.
- Ошибка импорта отображается как **BROKEN** с причиной.

Плагины исполняются с правами текущего пользователя. Это не песочница: импорт модуля запускает Python-код. Используйте только плагины, которым доверяете.

## Контракт плагина

Создайте Python-файл в `plugins/`. Имена файлов с начальным `_` зарезервированы для общих модулей. Минимальная декларация:

```python
PLUGIN = {
    "name": "example_lookup",
    "description": "Searches the configured catalogue.",
    "parameters": {
        "type": "OBJECT",
        "properties": {
            "query": {"type": "STRING", "description": "Text to find"}
        },
        "required": ["query"],
    },
}

def run(parameters, player=None, session_memory=None):
    return f"Looked up: {parameters.get('query', '')}"
```

`name` — уникальный Python-идентификатор длиной до 64 символов; `description` — непустая строка; `parameters` — схема типа `OBJECT`, понятная выбранному движку. `run` должна быть синхронной и возвращать краткий результат. Загрузчик передаёт `player` и `session_memory` только если они указаны в сигнатуре (либо оба при наличии `**kwargs`). Исключение перехватывается и записывается в лог. Для долгих операций не блокируйте цикл разговора; используйте фоновые механизмы проекта и таймауты.

Дополнительные поля `PLUGIN`: `behavior` (`BLOCKING` или `NON_BLOCKING`), `scheduling` (`WHEN_IDLE`, `SILENT`, `INTERRUPT`), `tier` (`core`/`extra`) и короткое описание `brief`. Неизвестные значения проверяются загрузчиком и могут быть проигнорированы.

## Форма настроек

При необходимости объявите `PLUGIN_SETTINGS`; UI покажет форму в **PLUGIN SETTINGS**:

```python
PLUGIN_SETTINGS = {
    "namespace": "example_service",
    "title": "Example service",
    "fields": [
        {"key": "api_key", "label": "API key", "type": "password", "default": ""},
        {"key": "base_url", "label": "Server URL", "type": "text",
         "default": "https://example.invalid"},
    ],
    # Необязательно: {"label": "TEST CONNECTION", "run": callable}
}
```

Используйте существующие схемы `plugins/spotify_control.py`, `plugins/obsidian_vault.py` и `plugins/telegram_remote.py` как примеры. Типы полей и формат TEST сверяйте с реализацией UI. Секреты храните через конфигурацию; никогда не выводите их в лог.

## Проверка и структура

Проверьте импорт, уникальность имени, схему, некорректный ввод, таймауты, успешный сценарий и отказ сервиса. Затем перезапустите приложение, проверьте карточку **PLUGINS**, настройки и TEST. Изменения Python-кода не подхватываются горячей перезагрузкой.

```text
plugins/                  плагины
plugins/_*.py             общие helpers
core/plugin_loader.py     поиск, валидация, запуск
memory/config_manager.py  настройки и ON/OFF
ui.py                     менеджер и формы настроек
```
